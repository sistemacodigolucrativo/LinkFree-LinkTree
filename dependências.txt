AMBIENTE ATUAL OBSERVADO
Ubuntu 24.04.4 LTS; Nginx 1.24; PHP CLI/FPM 8.3.6; MariaDB 10.11.14; Composer 2.11.2; Node.js 22.23.2 e npm 10.9.8. Serviços nginx, php8.3-fpm e mariadb ativos. Produção em /srv/linkstack, PHP-FPM como www-data, URL HTTPS, banco MySQL/MariaDB local, cache e sessão em arquivos e fila sync. APP_DEBUG=false. A configuração real e credenciais são específicas do servidor e não devem ser copiadas ou publicadas. APP_URL estava vazio na inspeção; uma instalação nova deve definir a URL correta.

REQUISITOS DE EXECUÇÃO
Linux com PHP >=8.0 (composer.json); o ambiente testado usa PHP 8.3. Extensões verificadas pelo index.php: bcmath, ctype, curl, dom, fileinfo, json, mbstring, openssl, pcre, PDO, tokenizer, xml e iconv. PDO MySQL para MariaDB/MySQL ou PDO SQLite para SQLite; gd e zip são usados por recursos de imagens e arquivos. Na máquina também estão disponíveis exif, mysqli, sqlite3, XMLReader/XMLWriter e outras extensões padrão. Composer/lockfile detalha as dependências PHP e suas versões; vendor já é versionado no repositório. O projeto também contém assets compilados. Node/npm, Laravel Mix 6 e dependências do package-lock são necessários para recompilar CSS/JS, não para executar os assets já fornecidos. Git e conexão com GitHub são necessários para obter/atualizar o código. Correio SMTP, Redis, AWS e provedores OAuth são opcionais e precisam de credenciais próprias quando utilizados; não estão configurados pelo instalador proposto.

SERVIDOR E DADOS
A raiz web é linkstack/ (index.php fica nessa pasta, não em public/). PHP-FPM e Nginx precisam da mesma versão PHP e de acesso aos arquivos. Negar acesso HTTP a arquivos ocultos, .env, código PHP exceto index.php, diretórios internos, bancos, arquivos de configuração, logs e backups; encaminhar rotas inexistentes a index.php. uploads demandam limite adequado (20 MB na instância). HTTPS exige domínio apontado para o servidor, portas 80/443 e certificado válido; a instalação existente usa Let's Encrypt. Diretórios storage, bootstrap/cache e os arquivos alterados pela aplicação precisam de escrita pelo usuário PHP. A etapa web também cria/remove INSTALLING e INSTALLERLOCK e altera .env. Não conceder acesso público ao instalador: ele possui rota /skip que cria usuário padrão; bloquear essa rota e proteger toda a configuração inicial. Concluir cadastro e remover a proteção apenas quando a instalação terminar.

BANCO E INICIALIZAÇÃO
A aplicação suporta SQLite e MySQL/MariaDB; produção usa MariaDB. O repositório contém database/database.sqlite já inicializado com dados de catálogo e sem usuários; não reutilizar dados pessoais nem um banco de uma instalação anterior. A seleção MySQL no instalador web exige banco vazio, usuário e senha próprios; aplica migrações e seeders e inclui a correção que evita duplicar PageSeeder e ButtonSeeder. O .env versionado fornece opções específicas do LinkStack ausentes em .env.example; para uma nova instalação, gerar APP_KEY independente, configurar APP_ENV=production, APP_DEBUG=false, URL e banco próprio, preservando as demais opções de aplicação e sem transportar segredos de outra instância. Uma instância nova deve começar com INSTALLING e sem INSTALLERLOCK. Configuração avançada depende de config/advanced-config.php ou de storage/templates/advanced-config.php e storage/app/ISINSTALLED.

CACHE, PUBLICAÇÃO E VALIDAÇÃO
Não executar config:cache, route:cache ou optimize: o projeto consulta env() diretamente e esses caches quebram funcionalidades e rotas autenticadas. Após publicação usar config:clear, route:clear e view:clear. Validar instalação web protegida, criação do primeiro administrador, conclusão do assistente, login, dashboard e gravação de perfil em banco isolado. Home 200 e tela protegida 302 isoladamente não comprovam funcionamento autenticado. scripts/atualizar-linkstack.sh é um atualizador e preserva dados de instalação; não substitui um instalador inicial.

PREPARADOR DE VPS (instal.sh)
O preparador destina-se a uma instalação nova no Ubuntu 24.04 e clona automaticamente a branch main deste repositório. Instala Nginx, PHP 8.3 CLI/FPM e extensões, MariaDB, SQLite, Git, Composer, Node.js, npm, Certbot e ferramentas auxiliares; confere os requisitos de plataforma do Composer. Copia a aplicação para /srv/linkfree por padrão (alterável com --dest), gera uma chave própria e prepara a configuração inicial para o assistente web. Cria um banco MariaDB e usuário próprios; as credenciais ficam em arquivo protegido sob /root, indicado ao final, para uso opcional na etapa MySQL. SQLite continua disponível. O Nginx limita o acesso ao assistente ao IP/rede fornecido e bloqueia /skip; depois da conclusão o site fica acessível normalmente.
Com --email, o Certbot tenta obter um certificado Let's Encrypt por HTTP: domínio já apontado para a VPS, portas 80 e 443 acessíveis e ausência de conflito para o domínio são necessários. Alternativamente, forneça --cert e --key para um certificado existente. Execute bash instal.sh --help para opções. A emissão real de certificado, instalação dos pacotes em máquina limpa e configuração integral dos serviços ainda precisam ser validadas em VPS descartável; testes em ambiente isolado cobriram a preparação, o assistente SQLite, login e perfil, e migrações/seeders do MySQL.
